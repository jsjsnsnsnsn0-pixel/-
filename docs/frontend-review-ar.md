# تقرير مراجعة وإصلاح Front-end — TotiChat

تاريخ المراجعة: 2026-10-05. الفرع: `frontend-fixes`.
نقطة البداية: `origin/main` عند commit `52714370de7e985eab16f550057b747ebe15bd1b`، ويتضمن إصلاح محاذاة شاشة الرسائل.

## 1. الحالة قبل الإصلاح

المشروع React 19 + TypeScript + Vite 8 + Tailwind 4. التنقل محلي بواسطة `AppContext`، ويعتمد العرض على `activeTab` و`activeSubScreen` و`activeRoom`. ملف `AppContext` يجمع حالة الواجهة مع المصادقة وإجراءات الحساب؛ لذلك تُرك دون تعديل. `RealtimeRankingsProvider` و`systemNotificationService` يستخدمان تخزين المتصفح، والتغييرات فيهما محصورة في التحقق من بيانات هذا التخزين قبل العرض. لا يحتويان على API أو استعلامات قاعدة بيانات.

تمت مراجعة بنية المصدر والشاشات والمكونات والمداخل والخدمات والسياقات والأنواع، وفحص imports وhooks والمؤقتات وlisteners ومسارات الصور والتخزين والتنقل والنماذج. جرى اختبار العرض الفعلي لكل الشاشات الفرعية المسجلة، والنوافذ الرئيسية، ومقاسات متعددة. لا تعني هذه المراجعة اختبار كل ميزة ضد Backend حقيقي.

الفحص الأولي: `npm ci --ignore-scripts` نجح؛ `npm run lint` فشل بخطأ TypeScript واحد؛ `npm run build` نجح. لا يوجد script مستقل لـ Tests أو ESLint. تشغيل التطبيق دون متغيرات Supabase ينتج خطأ module import وصفحة فارغة.

## 2. الأخطاء المكتشفة والإصلاحات المنفذة

- **TypeScript:** كائن مستخدم الدعم في شاشة الوكالة يفتقد `isOnline` المطلوب. أُضيف الحقل للكائن، دون تغيير نوع `User` أو أي عقد بيانات.
- **صور الإنتاج:** روابط `/src/assets/images/...` النصية لا تجعل Vite يضمّن الصور في Build. أُضيف plugin لمرحلة البناء فقط، يصدر الصور بمساراتها الحالية. تم التحقق من وجود جميع الصور الـ128 في الناتج ومطابقة محتواها للمصدر؛ لم تتغير ملفات الصور نفسها.
- **التنقل:** زر إنشاء الغرفة يفتح اسم شاشة غير مسجل؛ أُصلح ليفتح تبويب الإنشاء. زر دعم الوكالة كان يعود للخلف؛ أصبح يفتح المحادثة. زر دعم الهدية المخصصة كان يفتح مساراً غير موجود؛ أصبح يحدد مستخدم الدعم ويفتح المحادثة الموجودة.
- **التنقل داخل الغرفة:** أولوية `activeRoom` كانت تمنع عرض الشاشات التي تُفتح من الغرفة. أصبح عرض الغرفة مشروطاً بعدم وجود شاشة فرعية، مع الحفاظ على `activeRoom` والعودة إليها عند إغلاق الشاشة. أُضيف عرض شاشة الرسائل عند فتحها من الغرفة.
- **الشاشات غير المسجلة والزوار:** عوضاً عن صفحة فارغة، تظهر حالة واضحة وزر رجوع. لم تُختلق بيانات زوار أو API؛ استكمال القائمة الفعلية مؤجل.
- **المحادثة:** نُقل Hook الموجود بعد شرط الخروج، وأُضيفت حالة غياب مستخدم المحادثة. أُزيل إرسال الرسالة إلى حالتين في وقت واحد عندما توجد محادثة، لمنع ظهورها مرتين. أصبحت الرسالة الصوتية المحلية تمرّ بمسار المحادثة الموجودة أيضاً. أُضيفت معرفات محلية متمايزة، وتنظيف الحالة والمؤقتات عند تغيير المحادثة.
- **المؤقتات:** أُضيف Hook صغير يلغي مؤقتات الواجهة عند unmount أو تغير الحوار/المحادثة، ويستبدل مؤقت الإشعار القديم لمنع إخفاء إشعار أحدث. مفاتيح مستقلة تحفظ الردود المتعددة والتسجيل والنسخ في المحادثة. لا يُجدول مؤقت بعد unmount.
- **JSON والتخزين:** لم تعد `null` أو object أو JSON غير صالح تصل إلى المصفوفات المعروضة. تُقبل عناصر بالحقول اللازمة للعرض، وتُتجاهل العناصر التالفة، مع fallback آمن عند منع localStorage. لا تتغير مفاتيح التخزين أو العقود.
- **العدّاد:** كان انتقال الثواني للصفر يضبط الدقائق على 59 بدلاً من إنقاص دقيقة. أُصلح الإنقاص، وأصبح interval يعمل عندما تكون النافذة مفتوحة فقط.
- **الحافظة:** لا تظهر رسالة نجاح إلا بعد نجاح النسخ، وتُلتقط حالات الرفض وعدم توفر API في WebView دون unhandled promise.
- **الصور البديلة:** مُنع إعادة تحميل fallback مكسور إلى ما لا نهاية، وتُعاد محاولة الصورة عند تغير المصدر. إذا فشلت الصورة الافتراضية في `UserAvatar` يظهر حرف بديل. استُبدلت أربعة روابط صور غير موجودة بصور موجودة، لأنها أخطاء فعلية.
- **اختيار صورة محلية:** تنظيف FileReader عند المغادرة/اختيار ملف أحدث، ورسالة خطأ للملف غير الصوري أو فشل القراءة، وإفراغ input للسماح بإعادة اختيار الملف نفسه.
- **الهاتف:** المحادثة ذات ارتفاع viewport ديناميكي وfeed مستقل قابل للتمرير؛ شريط الإدخال لا يتمدد خارج العرض، والنص الطويل يلتف. أُضيف دعم safe area للشريط السفلي والمحادثة والغرفة، دون إعادة تصميم.
- **أخطاء صغيرة:** منع تكرار ضغط إرسال الهدية بعد نجاحها وتكرار إنشاء الغرفة أثناء الانتظار، وإزالة مسافات البحث الزائدة.

**إصلاح MessagesScreen محفوظ:** لم تُغيّر شبكة الأعمدة أو أحجامها أو المحاذاة أو ترتيب الرسالتين أو النصوص أو الصور الأصلية. التغيير الوحيد فيه هو حماية fallback. اختبار المتصفح أثبت تطابق أعمدة الصفين وبقاء رسالة النظام فوق الرسالة الرسمية.

## 4. Deferred بسبب Backend work

هذه النقاط لم تُنفّذ احتراماً للحدود المطلوبة:

1. **غياب إعدادات Supabase:** `src/services/supabase.ts` يرمي خطأ قبل mount عند غياب `VITE_SUPABASE_URL` أو `VITE_SUPABASE_PUBLISHABLE_KEY`. لا يمسك ErrorBoundary أخطاء module import. تُرك الاتصال والمصادقة دون تعديل؛ يلزم توفير الإعدادات والتحقق من سلوك bootstrap مع فريق Backend.
2. **AppContext:** يجمع المصادقة والحساب والمحفظة والغرف مع حالة العرض. تُرك كله دون تعديل. يشمل ذلك عدم التحقق الكامل من profile cache، parsing للأرقام المعروضة بفواصل، مؤقت gift overlay، وتزامن بيانات المستخدم/المقاعد بين الحالات.
3. **تسجيل الهاتف/Google وتعبئة الملف ونموذج دخول الوكالة:** توجد مسارات محلية وتجريبية وتكاملات ينبغي مراجعتها مع Backend. لم تتغير Authentication أو كتابة profiles أو تدفق OAuth.
4. **الشحن:** تُرك `RechargeScreen.tsx` وطلبات `recharge_packages` و`create_recharge_request` كما هي. ينبغي معالجة rejection الاستثنائي، حالات التحميل/الفراغ، مؤقتات النجاح، وتأكيد الطلبات طبقاً للعقد النهائي، دون تخمينه هنا.
5. **الأموال والمكافآت والمتجر وVIP والترتيبات:** توجد إجراءات تجريبية تمنح أو تخصم قيمة محلياً، ودعم تجريبي قد يشحن الذهب تلقائياً. حساب النقاط وتأكيد الملكية والدفع والاستحقاق يحتاجان Backend موثوقاً؛ لم تتغير هذه الإجراءات. حدث إرسال هدية الغرفة لا يجد مستمعاً في Provider الخاص بالترتيبات، وربطه مؤجل حتى تتضح آلية Backend كي لا تتكرر النقاط.
6. **الزوار والأصدقاء والرسائل:** لا يوجد مصدر زوار مسجل؛ أُضيفت حالة آمنة بدلاً من الشاشة الفارغة فقط. لا توجد إضافة API أو بيانات مختلقة. حفظ محادثات جديدة بلا conversation قائم، الإرسال الحقيقي، والرسائل الصوتية الحقيقية تحتاج اتفاق Backend؛ التسجيل الحالي محاكاة محلية محفوظة.
7. **APK workflow:** يحتوي على وضع demo يستبدل خدمة الاتصال أثناء CI. تُرك `.github/workflows/main.yml` دون تعديل لارتباطه بالمصادقة/إعداد التشغيل. لا يُعد APK demo تحققاً من Backend الحقيقي.

## 5. نتائج الفحوص

| الفحص | قبل الإصلاح | بعد الإصلاح |

| Tests في package.json | لا يوجد script | لم يُضف إطار أو dependency. |

| مطابقة أصول الإنتاج | الصور لا تصدر بالروابط النصية | 128/128 صورة موجودة ومطابقة byte-for-byte، لا توجد مراجع صور محلية مفقودة. |
| مراجعة التغييرات | — | فحص whitespace والمسارات المحمية وقسم Vite server. |

اختبارات العرض استخدمت استبدال خدمة الاتصال **داخل اعتراضات شبكة متصفح الاختبار فقط**، دون تعديل ملف الخدمة أو المصادقة في المستودع. نسخة الإنتاج الاختبارية بُنيت بقيم placeholder غير سرية، واختُبر ظهور شاشة الدخول وصورتها دون اتصال خارجي. لا تدل هذه الاختبارات على نجاح login أو recharge حقيقيين.

المقاسات المختبرة: 320، 360، 412، 768، 1280 px. لا overflow أفقي في الشاشات المقاسة: الرسائل والبحث وتعديل الملف والشحن والمحادثة. تم فحص لقطة شاشة المحادثة والرسائل بصرياً. جرى اختبار 25 حالة شاشة فرعية (منها مسار غير معروف)، والنوافذ الخمس الرئيسية، ورفض الحافظة، وصورة محلية، والـJSON التالف، ودقائق العدّاد، وترتيب Hooks، وعدم تكرار الرسائل، وإلغاء المؤقتات في StrictMode.

لا توجد page errors أو أخطاء React غير معالجة في اختبارات fixtures. رسائل console الخاصة بفشل الموارد الخارجية نتجت عن إيقاف طلبات الخطوط/Google/الصور الخارجية عمداً في الاختبار، وليست دليلاً على فشلها في الإنتاج. لم تُختبر خدماتها الحقيقية.

## 6. التحذيرات والمخاطر والتوصيات

- يستمر تحذير الحزمة الأكبر من 500 KB في Build ذي إعدادات الاتصال. تقسيم الشاشات بـ lazy imports يحتاج عملاً منفصلاً ومراجعة تحميلها.
- الأصول الحالية نحو 101 MiB؛ لم تُضغط أو تُغير حفاظاً على الهوية والصور. تضمينها يصحح الإصدار، لكنه يزيد حجم حزمة APK؛ ضغط الصور/تحميلها حسب الحاجة مرحلة أداء لاحقة.
- صور وخطوط خارجية تحتاج شبكة. ينبغي التحقق على اتصال ضعيف وعلى Android WebView حقيقي.
- browser mobile emulation لا يعادل اختبار APK، لوحة مفاتيح Android، أذونات الميكروفون أو الدفع أو OAuth على جهاز. هذه اختبارات المرحلة القادمة.
- fallback للشاشات غير المسجلة يمنع الفراغ، لكنه لا ينشئ ميزة الزوار الفعلية.
- يلزم اختبار التكامل الحقيقي بعد اكتمال Backend، ثم تشغيل فحوص login/logout والشحن وحفظ الملف والرسائل والغرفة بالتزامن مع إصدار الـAPI النهائي.
- لا يوجد ESLint أو test runner معرفان حالياً. يُنصح باعتماد فحوص الانحدار الملائمة في CI بقرار منفصل، دون تغيير workflow الحالي ضمن هذه المهمة.

## 7. سلامة Git والنتيجة

تم العمل في clone مستقل ونظيف، ولم يكن `frontend-fixes` موجوداً عند البداية. لم تُستبدل تغييرات Agent آخر ولم تُستخدم عمليات reset أو rebase أو force push أو merge. ملفات `AppContext.tsx` و`supabase.ts` و`LoginScreen.tsx` و`FillInfoScreen.tsx` و`RechargeScreen.tsx` والأنواع وملفات الحزم وworkflow بقيت دون تعديل. قسم `server` في Vite لم يتغير. نقطة `main` كانت لا تزال عند commit البداية عند المراجعة النهائية السابقة للرفع.

الفرع الوحيد للعمل والوجهة الوحيدة للرفع: `frontend-fixes` → `origin/frontend-fixes`. رقم commit وتأكيد الرفع بعد التحقق من المرجع البعيد يردان في رسالة التسليم النهائية؛ لا يُكتب داخل هذا commit ادعاء سابق لحدوث الرفع.

**التصنيف: 🟡 يحتاج بعض العمل.** الإصلاحات الآمنة للواجهة تمرّ بالفحوص؛ الجاهزية النهائية تتطلب إعداد الاتصال واختبارات التكامل واستكمال الوظائف المؤجلة مع Backend.
