## Standalone Admin Website
- Login: shared Supabase Auth email/password or Google OAuth.
- Gate: server-side dashboard_session with dynamic role permissions.
- Overview, user search, audited wallet adjustments/history, staff roles, agency requests, host/agency settlement reporting and owner-only settlement actions, gift/store catalogs, room moderation, support tickets, audit logs, beta telemetry and feature flags.
- Staff members receive the website link and authenticate individually; URL alone grants no privileges.
- Backend operations are existing planned server RPCs. UI uses text nodes (not raw HTML), no service_role key, idempotent finance request identifiers, confirmation prompts and permission-specific screens.
- Vercel build requires the exact existing TotiChat project URL and only a sb_publishable_ public key. Root Directory: admin-dashboard; independent Vercel project. Google OAuth redirect URLs must be configured externally.
- A dedicated GitHub Actions syntax/build smoke workflow is added. Passing that check is necessary but not sufficient for full mobile/security readiness.

## Blockers Before Production Activation
1. Review and apply pending beta migrations in order in a safe environment, reconciling GitHub versus Supabase migration history; never reset production.
2. Verify the owner identity in auth/admin_roles using an authorized operator, and ensure staff cannot self-assign the owner role.
3. Check financial RPC integrity: wallet idempotency, row locks, negative balance rejection, audit entries, and 30% diamond conversion; protect production balances.
4. Test monthly close with prepared data and rollback-only regressions; preserve accrued salary and agent commissions before zeroing operational monthly diamonds.
5. Confirm storage policies for agency documents, least-privilege support/room moderation and explicit authorization of SECURITY DEFINER functions.
6. Configure Supabase Auth redirect allowlist, publishable key and isolated Vercel project; verify browser session and cross-device updates.
7. Run full application unit, browser, Android and real two-device audio/music tests. No APK or production deployment is claimed here.

Conclusion: the independent website source is built and isolated in a feature branch; production backend activation and full end-to-end validation remain gated.
